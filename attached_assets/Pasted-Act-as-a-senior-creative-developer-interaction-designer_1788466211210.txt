Act as a senior creative developer, interaction designer, UX designer and front-end engineer. Build a polished, original website for **Larkin2** using the existing content, routes and assets in this Replit project.

Use https://www.dickclark.com as a reference for its cinematic presentation, typography, component structure, transitions and motion language. Take inspiration from its principles, but do not copy its branding, text, photographs, videos, logos, source code or exact page layouts. The completed website must clearly belong to Larkin2.

## 1. Brand-name rules

The official site and brand name is:

**Larkin2**

Use this exact spelling and capitalisation throughout the website.

Do not display it as:

* Larkin 2
* larkin2
* LARKIN2

The lowercase form may only be used where technically required, such as a domain, URL, username, file name or code identifier.

Use “Larkin2” in:

* Browser titles
* Page metadata
* Navigation
* Logo alternative text
* Footer copyright text
* Social-sharing metadata
* Contact forms
* Accessibility labels
* Loading screens
* Any visible brand references

## 2. Project objective

Create a premium, dark, media-led website that feels confident, cinematic and editorial.

The experience should combine:

* A restrained black-and-white visual system
* One carefully controlled accent colour
* Large editorial typography
* Strong use of photography or video
* Smooth scrolling
* Masked text reveals
* Scroll-triggered image reveals
* Refined hover interactions
* Cinematic page transitions
* Responsive layouts
* Excellent accessibility
* Reliable fallbacks for slower devices and browsers without WebGL

Do not create a generic corporate template. The visual hierarchy, spacing and movement should feel intentionally designed for Larkin2.

* Keep long text blocks between 35 and 60 characters wide.
* Use uppercase only for short navigation labels, categories and metadata.
* Do not capitalise ordinary words unnecessarily.
* Give headings generous space and allow them to become primary visual elements.
* Avoid placing important text inside images.
* Ensure all important text remains selectable and accessible.

## 9. Global motion tokens


Motion hierarchy:

* Small hover feedback: 300 to 400ms
* Text and control entrance: 700 to 900ms
* Image and video entrance: 900 to 1200ms
* Page transition: 600 to 900ms
* Avoid unnecessarily long animations.
* Use consistent easing across the entire project.
* Never animate every element simply because it is possible.

Create reusable animation primitives instead of writing unrelated animation logic for every section.

## 11. Button and link interactions

For important text links and buttons, create a masked text-swap effect:

* Place two copies of the visible label inside an overflow-hidden wrapper.
* The first label occupies the normal position.
* The second label begins directly below it.
* On hover or focus, move the first label upwards and bring the second label into place.
* Use a 300 to 400ms transition.
* Mark the duplicate visual label with `aria-hidden="true"` so screen readers do not announce the text twice.
* Keep one accessible name on the parent link or button.

For pill buttons:

* Include a small accent dot or arrow.
* On hover, slightly shift the text horizontally.
* Allow the dot or arrow background to expand subtly.
* Do not use large scaling effects.

For circular carousel arrows:

* Keep the arrow visible by default.
* On hover, move the original arrow out of the circle.
* Bring a second arrow in from the opposite direction.
* Scale a circular background from approximately `0.2` to `1`.
* Keep the full interaction near 400ms.
* Ensure buttons have at least a 44px interactive area.

## 14. WebGL requirements

Use Three.js or another WebGL layer only if curved video warping, media distortion or advanced canvas transitions are genuinely necessary.

WebGL must be progressive enhancement, not a requirement for accessing Larkin2.

Before creating a renderer:

* Detect WebGL support.
* Catch renderer-creation errors.
* Check reduced-motion preferences.
* Check for low-power or constrained devices where practical.

If WebGL is unavailable:

* Render a normal HTML `<video>` or `<img>` carousel.
* Preserve headings, controls and navigation.
* Remove distortion effects.
* Keep the page fully usable.
* Never leave an empty canvas or permanent loading screen.
* Never keep scrolling disabled because WebGL failed.

Build and test the non-WebGL version first. Add WebGL only after the normal version is complete.

## 15. Text reveal system

Create three reusable reveal styles.

### Large heading reveal

* Split the heading by line.
* Wrap each line in an overflow-hidden mask.
* Begin the visible line at `translateY(108%)`.
* Animate it to `translateY(0)`.
* Use approximately 800ms.
* Stagger words by approximately 90ms.
* Stagger lines by approximately 100ms.

### Supporting-text reveal

* Split supporting copy by visual line where practical.
* Begin each line at `translateY(105%)` with zero opacity.
* Animate it to its natural position and full opacity.
* Use approximately 1000 to 1200ms.
* Stagger lines by 100ms.

### Horizontal word reveal

* Begin words at `translateX(100px)`.
* Start with muted grey and reduced opacity.
* Move them to their normal position.
* Change their colour gradually to off-white.
* Use approximately 1000ms.

Accessibility requirements:

* Preserve the complete readable sentence in the semantic heading or paragraph.
* Mark generated word and line wrappers as `aria-hidden="true"`.
* Use an `aria-label` or visually hidden original string if necessary.
* Do not make screen readers read every word as a separate item.
* Do not split text when reduced motion is enabled.

## 27. Reduced motion

Implement a proper reduced-motion mode.

Use:

```css
@media (prefers-reduced-motion: reduce) {
  html {
    scroll-behavior: auto;
  }

  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

Also adjust JavaScript:

* Do not split text for animation.
* Do not start continuous marquees.
* Do not automatically advance carousels.
* Do not use parallax.
* Do not initialise decorative WebGL.
* Display final statistic values immediately.
