Accessibility review / 30 September 2026

HETV Opportunities Hub

Target: WCAG 2.2 AA. The public website was tested in a real Chromium browser at desktop (1280 × 900), mobile (390 × 844), and narrow CSS viewport (320 × 760, representing the reflow width expected at 400% zoom from 1280px). The staff CRM and separate portal were excluded.

Result: The initial 42 page/state snapshots had 32 automated rule violations affecting 77 elements. After fixes, 47 page/state snapshots returned zero detected axe violations and no document-level horizontal overflow. This is not a claim of full WCAG conformance.

Pages and states covered

Home, roles list and detail, opportunities list and detail, training, development, FAQs, privacy, terms, unsubscribe, optional preferences, and not-found. Additional states: active signup draft and expanded “Other” option; empty roles results; verification-code entry; private-link entry; verified preference editing with intercepted test responses; and the open mobile menu. No real email or unsubscribe was triggered by the audit.

Confirmed barriers fixed

  • Text contrast (1.4.3): Low-contrast signup, role count/detail metadata, and opportunity-card labels were darkened. These were the bulk of the automated failures.
  • Structure and keyboard access (1.3.1, 2.1.1): Corrected skipped heading levels, the not-found main landmark, a horizontally scrollable privacy table that lacked keyboard focus, and the home page’s main landmark/skip-link target.
  • Focus order and navigation (2.4.3, 2.4.7): Client-side page changes focus the new page heading; keyboard hash links focus their destination. The closed mobile menu is inert, and the open menu traps focus, provides a named dialog, supports Escape, and restores its opener. A browser keyboard check caught and fixed focus staying on the trigger during the opening transition.
  • Names, help and feedback (3.3.2, 4.1.2, 4.1.3): Corrected duplicated/hidden link labels, associated form hints and errors with relevant inputs, focused submission errors, and added live busy/dismissal feedback for subscription management and the cookie notice. Existing native labels and fieldset groups remain intact.

Manual and regression checks

  • Keyboard walkthrough in Chromium: first Tab reaches the skip link; Enter moves to main; client-side Roles navigation focuses its heading; mobile menu focus wraps and Escape returns to its opener.
  • Inspected a browser accessibility-tree snapshot for heading exposure. Sampled mobile target boxes: menu trigger 62 × 37px, cookie-dismiss button 88 × 38px, and signup action 312 × 48px. Text links have the inline-text target-size exception.
  • Ran the browser with reduced motion enabled. The site’s reduced-motion CSS and native-scrolling path were inspected; no animation-dependent control was required to finish the tested flows. The narrow-viewport scans found no document-level horizontal overflow.
  • Added focused component tests for menu focus and names, signup error focus, optional purpose help, management errors, and cookie dismissal. The public artifact typecheck and all 22 Vitest tests passed.

Limits and remaining verification

  • Screen-reader session not available: A browser accessibility tree is not a substitute for NVDA, VoiceOver, or TalkBack. Human assistive-technology testing remains necessary, especially for announcements and forms.
  • Contrast still needs manual visual review: axe marked 233 individual checks “incomplete” across the final snapshots (primarily contrast over complex/image backgrounds, plus some ARIA checks). Zero violations means none of its conclusive checks failed; it does not certify every image/video frame or overlay.
  • Coverage boundaries: The narrow CSS viewport tests reflow but were not a literal browser zoom session. Verified management used mocked API responses; real email delivery, account-specific data and production content were not tested. Touch target checks sampled key controls rather than measuring every target. Different dynamic records and future content may need another pass.
